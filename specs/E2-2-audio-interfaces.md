# E2-2 · Audio interfaces

- **Issue:** [#6](https://github.com/bjornpetersson1/solid-backup/issues/6)
- **Labels:** `E2 Audio`
- **Phase:** 2. Audio
- **Depends on:** E2-1 (#5)
- **Status:** Approved

## Summary
`IAudioInput` and `IAudioOutput` as callback-based interfaces, a PortAudio implementation that drives both from one duplex stream, a WAV-file input and an in-memory output for tests, and a minimal pipeline that connects them. A `--passthrough` flag lets the owner hear the microphone in the headphones.

## Goals
- Two audio interfaces that every later epic (analysis, synth, live mode) can build on, with tests that need no audio hardware.
- A real-time path that never allocates, locks or does I/O per buffer.
- A pass-through the owner can run to check the PortAudio implementation by ear.

## Non-goals
- Choosing devices by name, listing devices in the app, detecting a missing microphone permission or a speaker output (E2-3). `--passthrough` uses the default input and output devices.
- Analysis, harmony or synthesis (E3–E5); the pipeline's only processing for now is pass-through.
- Recording to WAV (E5-3); this issue only reads WAV.
- Resampling, 24-bit WAV, or other WAV encodings than those below.
- The dashboard, dropout counter on screen, or latency display (E6).
- Changing the menu (E6-2).

## Acceptance Criteria
1. **`IAudioInput` and `IAudioOutput` exist and are callback based.**
   - `IAudioInput` delivers mono `float` buffers of `BufferSize` frames to a handler as `ReadOnlySpan<float>`, and exposes its sample rate and buffer size.
   - `IAudioOutput` receives the processed buffer for the same callback, so with a duplex stream the output buffer is filled within the input's callback.
   - Both can be started and stopped, and stopping is idempotent; both are `IDisposable`.
2. **PortAudio implementations.**
   - The app project references `PortAudioSharp2` (the binding chosen in E2-1).
   - A PortAudio implementation opens one duplex stream on the default input and output devices, at `SampleRate` and `BufferSize` from the settings, mono in and stereo out (the mono signal on both channels), and exposes it as an `IAudioInput` and an `IAudioOutput`.
   - It counts input overflows and output underflows from the callback status flags, readable after or during the run without locks.
   - PortAudio is initialised and terminated exactly once per run, also when opening the stream fails.
3. **A WAV file can be run through the pipeline in a test without audio hardware.**
   - A WAV-file input reads 16-bit PCM and 32-bit IEEE float, mono or stereo (stereo is mixed down to mono), and delivers it in `BufferSize` chunks synchronously, as fast as possible; the last partial buffer is padded with zeros.
   - A WAV file whose sample rate differs from the requested rate, or with an unsupported format, gives an exception with a clear message; it is never resampled.
   - An in-memory output stores everything it receives in a buffer allocated before the run.
   - A test runs a WAV file (generated by the test into a temp directory, or a small fixture) through `AudioPipeline` with pass-through processing into the in-memory output, and the output equals the input samples (within 16-bit quantisation for a 16-bit file). The test project does not touch PortAudio.
4. **No allocation, locks or I/O per buffer.**
   - A test measures `GC.GetAllocatedBytesForCurrentThread()` across the pipeline's per-buffer path (input handler → processing → output), after warm-up, with the WAV input and in-memory output, and asserts 0 bytes.
   - The PortAudio callback contains no allocation, `lock`, `Monitor`, logging or console calls (checked in code review; it cannot run in CI).
5. **`SampleRate` is a setting.**
   - `appsettings.json` has `"SampleRate": 48000`; `AppSettings` has `SampleRate`; `SettingsValidator` accepts only 44100 and 48000 and otherwise gives a Swedish error, with a test; the README settings table lists it.
6. **The PortAudio implementation passes the microphone through to the output in a manual check.**
   - `dotnet run --project src/SolidBackup -- --passthrough` starts pass-through from the default input to the default output, shows a Swedish line saying that pass-through is running and how to stop, and stops with `q` or `Esc`, closing the stream and terminating PortAudio, then prints the overflow and underflow counts in Swedish and exits 0.
   - `Ctrl+C` also closes the stream cleanly.
   - If PortAudio cannot open the stream, a Swedish error message is shown and the exit code is 1 (no stack trace).
   - `--help` lists `--passthrough` with a Swedish description; a test checks this.
   - Hearing the microphone in the headphones is listed in the PR as an unchecked manual check for the owner.
7. **The canonical check passes.** `dotnet format --verify-no-changes && dotnet build -warnaserror && dotnet test` exits 0 from the repo root, on macOS and in CI on Ubuntu.

## Decisions
- **Callback model with one PortAudio duplex stream.** Input and output share one callback, which gives the lowest latency and needs no ring buffer between two streams. The WAV input and in-memory output drive the same handler synchronously in tests. (Owner's choice.)
- **Manual check through `--passthrough`.** A flag, not a menu item, so the menu stays as it is until E6-2. Uses the default devices; choosing devices comes in E2-3. (Owner's choice.)
- **WAV formats: 16-bit PCM and 32-bit float, mono or stereo, no resampling.** Covers ordinary recordings and generated test tones; a mismatched rate is an error. (Owner's choice.)
- **`SampleRate` setting, default 48000, only 44100 or 48000 allowed.** (Owner's choice.)
- **Builds on E2-1:** the binding is `PortAudioSharp2` and the default `BufferSize` is the one E2-1 recommended; if the spike's findings change either, this spec follows them.
- **Mono in, stereo out** (default): input is monophonic by requirement; headphones are stereo, so the signal goes to both channels.
- **Own WAV reader, no package** (default): the format subset is small, and the constitution prefers no new dependency when a built-in way exists.
- **Overflow/underflow counters as plain fields updated with `Interlocked`/`Volatile`** (default): lock-free, and the basis for the dropout counter in E6.
